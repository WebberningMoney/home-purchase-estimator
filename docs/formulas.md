# 計算規則

對應原本的 Google 試算表，程式在 `src/core`。

| 項目 | 規則 | 檔案 |
|---|---|---|
| 每月房貸 | 本息平均攤還 `P·i / (1-(1+i)^-n)`，利率 0 時為 P/n | `loan.ts` |
| 剩餘本金（自動） | 從起始日一期一期往下推：每期用當時的利率，利息＝餘額×月利率，還款＝用剩餘本金、剩餘期數與當時利率重算的月繳金。手動填了就以手動為準 | `loan.ts` |
| 適用利率 | 取已生效的最後一次「利率調整」，沒調整過就是起始利率 | `loan.ts` |
| 已繳月數 | 滿月才算；結束日的日數小於起始日就少 1 | `loan.ts` |
| 剩餘月數 | 有起始日與年期：年期×12−已繳；否則用 NPER 反推 | `loan.ts` |
| 目前月繳金 | 手動填的優先；否則用「目前利率、剩餘本金、剩餘月數」重算（利率調整後銀行也是這樣重算） | `loan.ts` |
| 房地合一稅 | 持有 ≤2 年 45%、≤5 年 35%、≤10 年 20%、更久 15%；自住滿 6 年免 400 萬 | `tax.ts` |
| 資產可動用 | 各項市值 × 動用比例；美股以美元計、比特幣以顆數計，換匯後相加 | `assets.ts` |
| 現金推移 | 480 個月逐月：收入 − 生活費 − 新房貸（寬限期只繳利息、年期後為 0）− 保留貸款 | `cashflow.ts` |
| 存款續航 | 累計現金第一次變負的前一個月；從不變負為「撐過全程」 | `cashflow.ts` |
| 存款續航等級 | 不耗用現金＝無風險；耗用現金時，撐不到中風險門檻（預設 12 個月）為高風險、達到中風險門檻未滿低風險門檻（預設 36 個月）為中風險、達到低風險門檻為低風險。中風險門檻不得高於低風險門檻 | `cashflow.ts` |
| 收入中斷壓力測試 | 標「可能中斷」的收入扣掉後，每月缺口＝生活費＋年還款/12−剩餘收入；買完房的現金（扣預備金）÷缺口＝可撐月數，用同一套門檻評等級；沒有缺口＝不受影響 | `feasibility.ts` |
| 買房現金檢查 | 可動用現金 − 自備款 − 手續費 − 裝潢 − 其他 − 預備金 ≥ 0 | `feasibility.ts` |
| 每年還款檢查 | 年還款 ≤ 預算為通過；不耗用現金但儲蓄不足、耗用現金，其餘為超出預算 | `feasibility.ts` |
| 總結 | 兩項通過＝可行；現金通過且年還款為儲蓄不足或耗用現金＝有條件可行；其餘不可行 | `feasibility.ts` |
| 賣屋時的貸款 | 舊屋房貸（類型＝mortgage）賣屋時一定全部還清；信貸等其他貸款看「賣房後一次還清」。還清要出本金加違約金 | `feasibility.ts` |
| 賣屋實拿現金 | 賣價 − 賣方手續費 − 房地合一稅 − 土地增值稅與其他費用 − 還清的貸款 | `feasibility.ts` |
| 不賣舊屋 | `seller.enabled` 關閉：賣價、賣方費用、房地合一稅、貸款清償全部為 0，所有貸款改成留著繼續繳 | `feasibility.ts` |
| 三條房價界線 | 在目前貸款成數與利率下，用二分法找出風險不超過某一級的最高房價：無風險、低風險（＝「最多買得起」）、中風險。再貴就是高風險 | `affordability.ts` |
| 年預算 | 年收入 − 生活費 − 每年想存的金額；每年還款（新房貸＋保留的貸款）超過它就是「達不到存款目標」 | `feasibility.ts` |
| 每年實際存得下 | 年收入 − 生活費 − 每年還款；負的代表每年要動用存款 | `feasibility.ts` |

## 風險等級與三條界線

整體風險等級由 `risk.ts` 的 `riskLevel` 決定，畫面上所有顏色與名稱都來自它：

| 名稱 | 顏色 | 條件 |
|---|---|---|
| 不耗用現金（無風險） | 綠 | 買房現金夠，且每年還款在年預算內（收入付得起生活費、貸款、還存得到想存的金額） |
| 耗用現金（低風險） | 藍 | 買房現金夠，且是下列其一：收入付得起但存不到預計存款（不耗用現金）；或要動用現金，但現金撐得過低風險門檻 |
| 耗用現金（中風險） | 黃 | 買房現金夠，要動用現金，撐的月數介於中、低風險門檻之間 |
| 耗用現金（高風險） | 紅 | 買房現金不足，或現金撐不到中風險門檻 |

`findPriceLimits` 從 0 到 10 億用二分法，分別找出「最高風險不超過無風險／低風險／中風險」的最高房價，結果取到 10 萬：
- 「最多買得起」＝低風險界線，右邊大數字與結論文字裡的上限都是它。
- 拉桿底色的分界、右邊的量尺都用這三條界線，不會各算各的。
- `tests/feasibility.test.ts` 有一致性測試，以及用獨立程式重算的對照數字。

原試算表的「反推」公式是近似的封閉解，數字會和這裡差一點，已不再使用。
